🚀 H5 加载页
1.1 功能概述

用户进入活动页时展示全屏加载界面，前端使用 pixi-live2d-display（MIT 开源，支持 Cubism 4）加载 Live2D 模型资源包（.model3.json + 贴图素材）。加载完成后自动淡出，进入主战场页面。活动面向全平台所有用户，无准入门槛。

1.2 视觉元素
  • 退出按钮：左上角圆形半透明按钮（32×32px），chevron-left SVG 图标，点击退出活动页返回上级
  • 品牌 LOGO：渐变色 "⚡ MEIMODU" 文字，位于顶部居中
  • 角色剪影：Live2D 角色的简化 SVG 轮廓，带辉光滤镜（feGaussianBlur）和悬浮动画
  • 活动标题："魅魔来袭，召唤挑战"
  • 进度条：渐变色（紫 → 粉），带高光扫过动画
  • 百分比数字：JetBrains Mono 等宽字体
  • 加载阶段文字：动态切换的加载状态描述
  • 呼吸光点：底部三点波浪动画
1.3 加载阶段序列

进度条依次经过以下阶段，每阶段随机间隔 280ms ~ 550ms：

  • 8% — 初始化渲染引擎…
  • 20% — 加载 Live2D 模型文件…
  • 38% — 解析骨骼与网格数据…
  • 54% ~ 78% — 加载纹理贴图（1/3 ~ 3/3）…
  • 88% — 绑定动作序列…
  • 95% — 加载背景资源…
  • 100% — 加载完成！
1.4 过渡行为

加载到 100% 后延迟 480ms，加载界面 opacity 渐变至 0 并设置 visibility: hidden。首次加载后不再重复显示（通过 h5HasLoaded 标记）。

1.5 兜底策略

当 Live2D 文件加载失败时（网络异常 / 文件损坏），前端展示静态图片兜底，不影响后续攻击功能正常使用。建议单形态资源包 ≤ 5MB，总资源接入 CDN 加速。

1.6 背景氛围

加载页背景包含两个径向渐变光球动画（紫色 + 粉色），通过 scale 呼吸动画营造宇宙氛围感，与主战场风格保持一致。

1.7 活动时间校验
  • 活动未开始：展示倒计时页面，隐藏攻击功能
  • 活动已结束：展示活动结束页，保留 "进度奖励" 入口供用户领取未领奖励
  • 时区规则：所有时间以服务端北京时间（UTC+8）为准
1.8 兼容性要求

目标平台为 H5 移动端网页（WebView 内嵌友好），需支持 iOS Safari 13+、Android Chrome 80+。

2.1 功能概述

主战场是活动的核心交互页面，整体采用深色宇宙风主题，纵向三段布局：顶部区域（约 10%）放置导航栏和倒计时；中部区域（约 60%）展示 Live2D 角色、血条系统和形态切换；底部区域（约 30%）放置攻击道具栏、任务入口和进度奖励入口。

活动目标：提高平台每日消耗总电量 & 充值订单数量，面向全平台所有用户，无准入门槛。

2.2 顶部导航栏
  • 返回按钮：圆形半透明按钮，chevron-left SVG 图标，点击返回上级页面
  • 活动倒计时：居中展示 "距结束 DD:HH:MM:SS" 格式，数字使用 JetBrains Mono 等宽字体，每个数字块有半透明背景框，冒号使用粉色 var(--pink)
  • 规则按钮：粉色边框胶囊按钮，点击弹出活动规则弹窗（内容由后台富文本配置，支持图文）
2.3 BOSS 血条（全服共享）

血条为全平台所有用户共享，任意用户攻击命中均会扣减全服血量。显示 当前HP / 总HP，渐变色填充（粉 → 橙），带高光扫过动画。

  • 总血量：后台配置，示例 100,000 点
  • 当前血量：实时展示，所有用户攻击后实时更新
  • 阶段标记：白色竖线 + 金色编号标签（②③④），对应后台配置的里程碑节点血量值；未解锁节点显示锁图标，已解锁显示对应形态缩略图
  • 阶段解锁：全服血量首次跌破阈值时，该阶段新形态自动解锁（全平台所有用户同步解锁）
  • 血条归零：总血量归零后活动继续运行至结束时间，不提前终止。用户仍可继续攻击，累计攻击伤害用于解锁个人进度奖励
  • 后台调整：支持后台手动修改当前血量（运营调整节奏），修改后实时生效
  • 实时同步：推荐轮询（间隔 3s），无需 WebSocket，降低服务端压力
2.4 Live2D 角色区域

页面中央（约 60% 区域）展示 BOSS 角色的 Live2D 模型（原型用 SVG 占位），使用 pixi-live2d-display 库渲染。角色具有悬浮动画和辉光投影效果。文件来源为后台上传的 Live2D 模型文件（.model3.json + 资源包）。

  • 初始状态：展示第一个默认形态（阶段 0）
  • 命中反馈：角色抖动 0.4s + 亮度提升 + 粒子爆发，播放对应道具的受击动作（由后台配置动作名称）
  • 形态切换动画：播放过渡动画效果，切换后攻击动画均使用新形态对应动作
  • 背景切换：不同形态对应不同视差背景（后台可配上传）
2.5 形态选择栏（右侧）

右侧纵向排列的形态切换芯片。每个形态显示图标 + 名称。用户可随时手动切换已解锁的任意形态，无限制。形态数量由后台配置，每个形态对应一套独立 Live2D 文件。

  • 🌟 初始 — 默认形态，始终解锁
  • 🌸 觉醒 — HP ≤ 75% 全服同步解锁
  • 🔥 炽焰 — HP ≤ 50% 全服同步解锁
  • 💀 暗影 — HP ≤ 25% 全服同步解锁
  • 未解锁形态：显示锁定状态缩略图 + 降低透明度，点击提示 "消耗血量即可解锁"
2.6 武器道具区

底部展示两种攻击道具，中间用 "VS" 分隔。每种道具显示图标、名称、来源、剩余数量（角标）。

  • 道具 A：粉色系圆形按钮，完成单日消耗电量任务获得，触发 Live2D 动作 A
  • 道具 B：蓝色系圆形按钮，完成单日充值金额任务获得，触发 Live2D 动作 B
  • 道具不足时：弹窗提示 "道具不足，去完成任务获取"，跳转任务弹窗
  • 道具上限：每日道具上限 = 每日任务可完成次数（后台配置），不可跨日累积次数（已持有道具不重置，仅次数归零）
  • 活动结束后：未使用道具清零，不补偿
2.7 攻击流程

用户点击道具后执行以下流程：

  • 1. 消耗 1 个对应道具（立即扣减，不可撤回）
  • 2. 后台随机计算伤害值 1~10 点（伤害分布权重由后台配置），扣减全服血量
  • 3. Live2D 播放受击动作，前端产生飘字（-N）和粒子爆发效果

⚠️ 网络异常（请求失败）时不扣减道具，需前端做好失败回滚。

2.8 攻击伤害分布

每次攻击造成的伤害值和触发概率由后台自由配置。道具 A 和道具 B 拥有独立的伤害配置，运营可为每种道具添加任意数量的伤害值及其触发概率（总和 100%）：

  • 道具 A（⚡）：默认配置 5 个伤害值（1/2/3/5/10），偏向低伤害
  • 道具 B（🌊）：默认配置 5 个伤害值（1/3/5/8/10），偏向高伤害

攻击后产生飘字（-N）和粒子爆发效果，道具 A 为金色系粒子，道具 B 为蓝色系粒子。

2.9 底部操作按钮
  • 每日任务：金色指示点，有未领取奖励时右上角显示红点角标
  • 进度奖励：有可领取里程碑时右上角显示红点角标（与每日任务一致）
2.10 异常处理
  • 网络异常攻击失败：道具不消耗，前端回滚，提示 "网络异常，请重试"
  • 并发攻击血量超扣：后端 Redis 原子操作或数据库乐观锁，血量最低为 0 不出现负数
  • 重复点击防重：前端按钮 loading 态 + 后端 requestId 幂等去重
  • 后台调整血量低于已解锁阶段：不回收已解锁形态，仅影响后续阶段解锁逻辑
  • 重复领取奖励（异常请求）：后端幂等校验，返回已领取提示，不重复发放

3.1 功能概述

每日任务弹窗以底部弹出 Sheet 形式展示，用户通过完成消耗 / 充值任务获取攻击道具。任务进度实时同步（非 T+1），用户完成后即时反映进度。

3.2 触发方式

入口：主战场底部 "每日任务" 按钮
弹窗动画：从底部滑入，弹性缓动 cubic-bezier(0.34,1.56,0.64,1)
关闭方式：点击 ✕ 按钮 / 点击遮罩区域

3.3 任务类型

两种任务类型，各自独立计算进度：

  • 消耗任务 — 当日累计消耗电量 ≥ 后台配置阈值，奖励道具 A ×1
  • 充值任务 — 当日累计充值金额 ≥ 后台配置阈值，奖励道具 B ×1

充值计算以支付成功为准，退款 / 撤销不回滚任务进度。消耗数据实时同步。

3.4 任务卡片结构
  • 标签：任务类型胶囊标签（金色 / 蓝色）
  • 奖励预览：右侧显示道具名称和数量
  • 任务描述：如 "单日消耗 500 电量"
  • 进度条：渐变色，消耗任务金→粉，充值任务蓝→紫
  • 进度文字：如 "350 / 500 电量"
  • 领取按钮：未完成灰色禁用，已完成渐变色可点击
  • 次数限制：如 "今日剩余 3/3 次"，每日上限由后台配置
3.5 重置规则
  • 重置时间：每日 00:00（UTC+8 北京时间）自动重置任务进度和可领取次数
  • 已持有道具不重置，仅次数归零
  • 每日道具上限 = 每日任务可完成次数（后台配置）
  • 道具不可跨日累积次数（已持有道具不清除，仅任务次数重置）
  • 活动结束后，未使用道具清零，不补偿
3.6 领取交互

任务完成后需用户主动点击 "领取" 按钮，领取后道具即时入账。交互反馈：

  • 道具数量 +1 即时到账
  • 按钮变为灰色 "已领取" 状态
  • 剩余次数 -1
  • 主战场红点角标消失
  • 弹出 Toast 如 "道具A ×1 已入账！"
3.7 未领取处理

未领取的任务奖励在次日 00:00 重置前自动失效（具体策略可在后台配置）。

🎁 H5 进度奖励
4.1 功能概述

进度奖励弹窗展示玩家的个人累计伤害和对应的里程碑奖励。奖励类型分为两种：电量礼包和勋章奖励。触发条件为个人累计对全服血条造成的总伤害达到后台配置的里程碑值，与全服血条独立计算。

4.2 个人进度面板
  • 累计伤害数值：大号粉色数字（22px, 900 weight），展示个人累计伤害值
  • 距下一奖励提示：如 "还差 20 点伤害"，粉色高亮差值，展示个人累计伤害 / 下一个里程碑目标值
  • 所有完成提示：当全部里程碑达成，显示 "🎉 所有里程碑已完成！"
4.3 里程碑列表

纵向时间线布局，节点间有连接线。每个里程碑显示：

  • 节点图标：🔒（未达标）/ 🎁（已达标未领取，金色发光闪烁高亮）/ ✓（已领取，灰色）
  • 伤害阈值：如 "累计伤害达 50 点"
  • 奖励内容（电量类型）：显示 "⚡ +N 电量"，金色粗体文字
  • 奖励内容（勋章类型）：显示勋章预览图（32×32 圆角图标，渐变色背景）+ 勋章昵称（紫色/金色粗体）+ "勋章奖励" 灰色副标签
  • 领取按钮：未达标（禁用灰色）/ 可领取（金→橙渐变）/ 已领取（灰色 "已领取"）
4.4 里程碑配置

后台可自由增删节点、调整阈值和奖励数值。奖励类型有电量和勋章两种：

  • 电量奖励 — 即时到账的电量礼包，如 +500 电量、+2,000 电量
  • 勋章奖励 — 通过配置勋章 ID 关联勋章系统，自动回显勋章预览图和勋章昵称（如 "初级挑战者"、"魅魔征服者"），领取后展示在用户个人主页
4.5 领取规则
  • 进度达标后用户手动点击 "领取" 按钮，即时到账
  • 每个里程碑不可重复领取（后端幂等校验，异常请求返回已领取提示，不重复发放）
  • 领取后 Toast 提示：电量奖励 "⚡ +N 电量已到账！"；勋章奖励 "🏅 勋章「XXX」已解锁！"
  • 活动结束后，已达标但未手动领取的奖励自动发放至用户账户

7.1 功能概述

Banner 管理页用于配置活动入口的轮播 Banner 图，可设置图片、跳转目标活动和排序权重。顶部提供 Banner 总开关（关闭后前端不展示任何 Banner）和 "＋ 新增 Banner" 按钮。

7.2 Banner 列表

每条 Banner 包含：

  • Banner 图片：建议尺寸 750×200px，支持 JPG/PNG/WebP 上传，hover 显示上传提示
  • 跳转活动 ID：下拉选择已有活动
  • 排序权重：数值越小越靠前
  • 删除按钮：红色边框按钮，点击后二次确认删除
  • Banner 开关：每条 Banner 独立的 Toggle 控件，控制该条 Banner 是否在前端展示
  • 活动倒计时开关：每条 Banner 独立配置的 Toggle 控件，控制前端 Banner 的展示模式
7.2.1 单个 Banner 开关

每条 Banner 卡片底部有独立的 Banner 开关，控制该条 Banner 的展示状态：

  • 开启：该 Banner 正常在前端展示，右侧显示绿色「展示中」标签
  • 关闭：该 Banner 不在前端展示，右侧显示灰色「已隐藏」标签，倒计时开关区域置灰不可操作
  • 与总开关关系：Banner 总开关关闭时，所有 Banner 均不展示，与单个开关无关
7.2.2 活动倒计时开关

每条 Banner 底部有独立的倒计时开关，控制该 Banner 在前端的展示形式：

  • 开启：Banner 展示为「图片 + 文案 + 领取按钮 + 倒计时」模式，右侧显示渐变色领取按钮和 HH:MM:SS 倒计时，适合需要引导用户参与的活动
  • 关闭：Banner 仅展示图片，不显示领取按钮和倒计时，适合纯展示类运营位
  • 预览标签：开关右侧实时显示预览状态（绿点 "图片+按钮+倒计时" / 灰点 "仅图片"）
7.3 展示规则配置
  • Banner 总开关：Toggle 控件，关闭后前端隐藏所有 Banner 展示区域
  • Banner 轮播开关：Toggle 控件，开启后多 Banner 自动轮播
  • 轮播间隔：数字输入，单位秒，默认 5s
  • 单个 Banner 时不展示轮播指示器
7.4 操作交互

点击 "＋ 新增 Banner" 按钮新增空白条目。每条 Banner 右侧有独立删除按钮，删除后 Toast 提示 "🗑️ Banner 已删除"。图片上传后即时预览。

8.1 功能概述

活动配置是管理后台最核心的页面，包含 Live2D 活动的全部可配置项。分为基础配置、Live2D 配置、BOSS 血条管理、道具配置、进度奖励五大板块。所有修改保存后实时生效。

8.2 活动开关
  • 活动总开关：关闭后用户无法访问活动 H5 页面（一键暂停/恢复）
8.3 活动基础信息
  • 活动名称：必填，影响 H5 页标题显示和活动列表的活动名称
  • 起止时间：datetime-local 选择器，所有时间以服务端北京时间（UTC+8）为准
  • 规则说明：多行文本域（支持富文本图文），前端按换行分段展示于规则弹窗
8.4 Live2D 形态管理

支持多个 BOSS 形态（数量由后台配置），每个形态对应一套独立 Live2D 文件。前端使用 pixi-live2d-display 库渲染（支持 Cubism 4）。每个形态包含：

  • 形态名称和图标：如 🌟 初始形态、🌸 觉醒形态
  • Live2D 模型上传：.zip 文件包（含 .model3.json + 贴图素材），建议单形态 ≤ 5MB，接入 CDN 加速
  • 背景图上传：1920×1080 或 750×1624，支持 JPG/PNG/WebP
  • 解锁触发：默认 / HP 降至 75% / 50% / 25%（全服同步解锁）
8.4.1 添加形态表单

点击 "＋ 添加形态" 展开表单面板（紫色高亮边框）：

  • 形态名称：必填，自定义名称如"炽焰形态"
  • Live2D 文件包：拖拽或点击上传 .zip 文件，包含 .model3.json 及贴图素材
  • 形态背景图：可选上传，未上传时使用默认动态星空背景
  • 解锁触发节点：下拉选择对应血量阈值
  • 形态图标：输入 Emoji 作为形态标识
8.4.2 动作映射配置

每个形态需配置动作 ID（必须与 .model3.json 中定义的动作名完全一致）：

  • 道具 A 攻击动作：如 motion_attack_lightning
  • 道具 B 攻击动作：如 motion_attack_water
  • 待机动作（循环）：如 motion_idle，无交互时持续播放
  • 形态切换动作：切换形态时播放的过渡动画效果
8.5 BOSS 血条管理
  • 总血量：必填数值，默认 100,000，修改后实时生效
  • 当前血量：可运营手动干预（如调整活动节奏），实时生效标记
  • 血条预览：可视化当前血量占比，显示实时百分比
  • 形态解锁节点：由 Live2D 形态管理中各形态的「解锁触发节点」配置控制（见 8.4）
  • 归零处理：血量归零后活动继续运行至结束时间，不提前终止
8.6 道具配置

道具命名、伤害范围、触发概率和获取任务合并为单个道具卡片统一配置。每个道具独立一张卡片（粉色边框 = 道具 A，蓝色边框 = 道具 B）：

  • 道具名称：自定义道具显示名称（影响前端 H5 展示）
  • 伤害值与触发概率：以行列表形式自由配置，每行一个伤害值及其触发概率。支持增删改：「+ 添加伤害值」新增行，每行右侧 × 按钮可删除，伤害值和概率均可编辑。每行有概率柱可视化预览
  • 独立校验：每个道具内所有行的触发概率合计必须等于 100%，否则标红警示不可保存
  • 获取任务：配置获取该道具的任务阈值和每日上限次数（道具 A 为消耗任务，道具 B 为充值任务）
  • 重置规则：每日 00:00 UTC+8 自动重置任务进度和次数，已持有道具不重置
  • 设计意图：允许运营为不同获取难度的道具配置差异化的伤害分布（如充值道具伤害更高），丰富策略玩法

后端使用 Redis 原子操作确保血量扣减原子性，防并发超扣。消耗数据实时同步（非 T+1），充值以支付成功为准。

8.7 个人进度里程碑

可增删里程碑节点，每个节点配置：

  • 累计伤害阈值：数字输入（基于个人对全服血条的总伤害）
  • 奖励类型：下拉选择 电量 或 勋章
  • 电量奖励：数字输入奖励电量值（即时到账）
  • 勋章奖励：输入勋章 ID（数字），系统自动匹配并回显勋章预览图和勋章昵称，匹配成功后显示 "已匹配" 状态
  • 每个节点不可重复领取（后端幂等校验）
  • 活动结束后已达标未领取的奖励自动发放

9.1 功能概述

Banner 入口展示在平台首页内容流顶部（筛选栏下方），用户无需进入活动页即可看到活动 Banner。Banner 支持左右滑动轮播，点击后跳转至对应活动 H5 页面。

9.2 Banner 样式
  • 容器：圆角卡片（14px），粉色描边（2px #FF2D87），内部深色渐变背景，带粉色 box-shadow 发光
  • 左侧 Logo：44×44 圆角图标，平台品牌色渐变（橙→金），展示平台 Logo
  • 中间文案：粗体白色活动标题，如 "限时狂欢！消耗电量领豪礼"
  • 右侧按钮：粉紫渐变胶囊按钮，文案 "可领取" / "领取电量"，下方灰色小字展示倒计时
9.3 轮播滑动
  • 滑动方式：手指左右滑动切换 Banner，支持触摸滑动和自动轮播
  • 指示器：底部居中圆点指示器，当前页为粉色长条（12px），其他为灰色圆点（6px）
  • 自动轮播：间隔由后台配置（默认 5s），用户手动滑动后暂停 10s 再恢复
  • 单条 Banner：不显示指示器，不启用滑动
9.4 红点提醒

红点采用容器级角标设计，固定在 Banner 轮播容器的右上角外侧，不随轮播内容切换而消失：

  • 角标样式：粉色背景 "可领取" 文字角标（非圆点），右侧带三角箭头指向 Banner，附带呼吸脉冲动画（badgePulse，2s 周期），确保用户注意到
  • 显示层级：角标 z-index: 10，悬浮于 Banner 容器之上，不受 overflow:hidden 裁切
  • 始终可见：无论当前轮播展示的是哪一条 Banner，只要任意活动有可领取奖励，角标始终显示
  • 首页图标红点：同时底部导航栏 "首页" 图标也显示红点（7px 粉色圆点），提示用户有待领取内容
  • 消除条件：用户领取所有可领取的任务奖励和进度奖励后，角标和首页红点同时消失
9.5 点击跳转

点击 Banner 任意区域跳转至对应活动 H5 页面（进入加载页 → 主战场）。跳转活动 ID 由后台 Banner 配置决定。

9.6 倒计时与展示模式

Banner 的展示模式由后台活动倒计时开关控制（每条 Banner 独立配置）：

  • 开启倒计时：Banner 右侧显示领取按钮（"领取电量"渐变胶囊）+ HH:MM:SS 倒计时，每秒刷新
  • 关闭倒计时：Banner 仅展示图片，不显示按钮和倒计时，适合纯展示运营位
  • 活动结束：Banner 自动隐藏；活动未开始时倒计时位置显示 "即将开始"

10.1 功能概述

用户活动数据管理页用于运营人员查看指定用户在各活动中的参与数据，并支持手动干预操作（解锁/锁定奖励、管理道具数量）。页面采用左右分栏布局：左侧为活动列表导航，右侧为选中活动的用户数据详情。

10.2 用户查询
  • 顶栏：显示当前查询用户的邮箱/用户名和 UID
  • 查询方式：通过 UID 或邮箱搜索用户，加载该用户参与的所有活动数据
  • 关闭：右上角 × 按钮关闭弹窗返回后台
10.3 左侧活动列表
  • 列表项：活动名称 + 活动 ID + 状态标签（启用 / 灰色禁用）
  • 选中态：左侧蓝色竖线 + 浅蓝背景 + 蓝色文字
  • 点击切换：切换右侧显示对应活动的用户数据
10.4 累计伤害总览
  • 大号数字：JetBrains Mono 等宽字体，36px 900 weight，展示该用户在活动期间的总伤害值
  • 单位标注：灰色小字 "点伤害"
  • 数据来源：实时读取该用户的攻击记录汇总
10.5 里程碑奖励进度

以表格形式展示每个里程碑节点的领取状态，每行包含：

  • 伤害阈值：大号数字展示目标伤害值
  • 奖励内容：卡片式展示，电量奖励显示黄色背景 + ⚡ 图标，勋章奖励显示勋章预览图 + 昵称
  • 状态标签：已完成（绿色）/ 待领取（橙色）/ 灰色未达标
  • 操作按钮：已领取/待领取行显示 "锁定奖励"（红色），未达标行显示 "手动解锁"（蓝色）
10.6 手动解锁 / 锁定
  • 手动解锁：运营可为未达标用户强制解锁某个里程碑奖励（如客诉补偿）。点击后弹出确认弹窗 "是否解锁权益？"，确认后该节点变为 "待领取" 状态
  • 锁定奖励：运营可锁定已领取/待领取的奖励（如发现异常数据）。锁定后用户无法再领取该节点
  • 确认弹窗：所有手动操作均需二次确认（取消 / 确认 按钮），防止误操作
  • 操作日志：建议记录操作人、操作时间、操作内容，用于审计
10.7 道具管理

运营可查看和修改用户当前持有的攻击道具数量，采用修改-确认两步操作防止误触：

  • 默认展示态：道具 A / B 双列卡片，显示道具图标、名称、来源和当前数量（大号等宽字体），右侧有「修改」按钮
  • 编辑态：点击「修改」后卡片切换为编辑态（蓝色边框高亮），显示当前值 → 修改值的变化，数量输入框可编辑
  • 确认操作：编辑态底部显示「取消」和「确认修改」两个按钮，点击「确认修改」后生效，「取消」恢复原值
  • 数量下限：道具数量最低为 0，不允许输入负数
  • 风险提示：卡片下方黄色警告条提示「修改道具数量将直接影响用户可攻击次数，请谨慎操作」
