# Badge Phase 2 勋章配置功能联调说明

> 版本: Phase 2 · 文档语言: 简体中文 · 受众: 甲方产品 / 技术 / 测试

---

## 1. 功能概述

Phase 2 在已有「勋章目录（Badge Catalog）」的基础上,新增 **勋章后台管理** 能力。

**业务目的**: 管理员可在后台自助配置活动所需的勋章资源,无需依赖开发介入即可完成勋章的录入、维护、上下架。

**功能模块**: 后台勋章管理页面 + 后台 CRUD API + 上下架工作流。已上线的勋章目录 API 保持不变,前端活动配置仍按原方式选择可用勋章。

**核心能力**:

- 勋章列表查看
- 勋章新建
- 勋章编辑
- 勋章启用 / 停用

---

## 2. 后台入口

**访问地址**: `/admin/badges`

**登录要求**: 必须先以管理员身份登录后台。未经授权访问会自动跳转至 `/admin/login`。

**操作步骤**:

1. 访问 `/admin/login` 完成管理员登录
2. 在管理员首页中找到「勋章管理」入口,或直接访问 `/admin/badges`
3. 进入后可对勋章资源进行增、删（编辑）、查、改（启停）操作

---

## 3. 功能列表

### 3.1 勋章列表

入口: `/admin/badges` → 默认页

**展示内容**:

| 字段 | 说明 |
|---|---|---|
| ID | 系统自动分配的数字 ID,不可修改 |
| 名称 | 勋章的中文/英文名称 |
| 缩略图 | 预览图,使用图片 URL |
| 描述 | 勋章说明文字 |
| 状态 | 「已启用」或「已停用」 |
| 创建时间 | 后台录入时间 |
| 更新时间 | 最近一次修改时间 |

**默认排序**: 已启用勋章在前,按 ID 从小到大排列;已停用勋章随后。

---

### 3.2 新建勋章

入口: 列表页右上角「新建勋章」按钮

**字段说明**:

| 字段 | 必填 | 类型 | 限制 | 说明 |
|---|:-:|---|---|---|
| 名称 | ✅ | 字符串 | 1–40 字符,trim 后判空 | 同一启用状态下名称不可重复 |
| 缩略图 | ✅ | URL | 必须是 `http://` 或 `https://` 开头的合法 URL | 推荐使用稳定可访问的图片地址 |
| 描述 | ❌ | 字符串 | ≤ 200 字符,trim 后判长 | 用于说明勋章含义 |
| 是否启用 | ❌ | 布尔值 | 默认 `true` | 新建后是否立刻可用 |

**保存结果**:

- 成功: 列表中新增一行,自动分配唯一数字 ID
- 失败: 表单提示具体错误原因,不会清空已填内容

---

### 3.3 编辑勋章

入口: 列表中任一勋章的「编辑」按钮 → `/admin/badges/{id}`

**可编辑字段**:

- 名称
- 缩略图
- 描述
- 是否启用

**不可编辑**:

- ID（由系统自动生成,创建后不可修改）

**保存规则**: 同新建,字段限制一致。名称修改时同样要求在启用状态下保持唯一。

---

### 3.4 激活 / 停用

入口: 列表中每行末尾的「启用 / 停用」开关按钮

**状态语义**:

| 状态 | 含义 |
|---|---|
| 已启用 (`active`) | 勋章可被活动配置引用,前台用户可正常获得 |
| 已停用 (`inactive`) | 勋章从活动配置候选中下架,但**保留在历史记录中**,已发放给用户的勋章不受影响 |

**操作特性**:

- 启用 / 停用操作幂等,重复点击同一状态不会报错
- 停用后再启用,勋章 ID 保持不变,可继续使用

## 4. 测试流程（甲方测试步骤）

请按以下步骤逐步验证,每一步独立检查结果:

### 步骤 1: 管理员登录

1. 浏览器打开 `/admin/login`
2. 输入管理员密码登录
3. 确认登录成功并跳转到后台首页

### 步骤 2: 进入勋章管理

1. 浏览器地址栏直接访问 `/admin/badges`
2. 确认能看到「勋章管理」标题 + 现有勋章列表
3. 列表应至少包含 ID 为 `10021`、`10035` 的两条记录

### 步骤 3: 创建测试勋章

1. 点击「新建勋章」按钮
2. 按下表填写:

   | 字段 | 测试值 |
   |---|---|
   | 名称 | 测试挑战勋章 |
   | 描述 | 联调用测试数据 |
   | 缩略图 | https://placehold.co/100x100/orange/white?text=TEST |
   | 是否启用 | 保持默认（启用） |

3. 点击「保存」

### 步骤 4: 确认列表显示

1. 返回列表页
2. 应在列表顶部（启用区）看到刚刚创建的「测试挑战勋章」
3. 核对字段值与填写一致

### 步骤 5: 编辑勋章

1. 在「测试挑战勋章」所在行点击「编辑」
2. 将「描述」改为「联调用测试数据 - 已编辑」
3. 保存
4. 列表中显示的描述应已更新

### 步骤 6: 启用 / 停用切换

1. 点击该勋章行的「停用」开关
2. 列表中此勋章应从「启用区」移至「停用区」（状态显示为已停用）
3. 再次点击「启用」开关
4. 应回到「启用区」,ID 与名称保持不变

### 步骤 7: 创建异常场景验证

1. 重复创建一个名称为「测试挑战勋章」的勋章 → 应提示「名称已被使用」
2. 缩略图填非 http(s) 开头的内容（如 `ftp://...`）→ 应提示 URL 不合法
3. 直接访问 `/admin/badges/99999999` 编辑不存在的 ID → 应提示「勋章 ID 不存在」

## 5. API 联调信息（技术人员）

**通用约定**: 所有接口需要管理员登录态（`admin_token` Cookie）,请求与响应均使用 JSON。

### 5.1 列表接口

```
GET /api/admin/badge
```

**用途**: 获取所有勋章（启用 + 停用）的列表。

**响应**:

```json
{
  "ok": true,
  "data": [
    {
      "id": 10021,
      "name": "初级挑战者",
      "thumbnail": "https://placehold.co/100x100/blue/white?text=B1",
      "description": "完成首个个人进度奖励的勇敢新星",
      "is_active": true,
      "created_at": "2026-09-02T12:37:54.983Z",
      "updated_at": "2026-09-02T12:37:54.983Z"
    }
  ]
}
```

**排序**: 已启用在前,按 ID 升序。

---

### 5.2 单条查询

```
GET /api/admin/badge/{id}
```

**用途**: 根据 ID 获取单个勋章详情。

**响应**: 同上 `data` 结构单对象。

**错误码**:

| 状态码 | 含义 |
|---|---|
| 400 | ID 为空或非数字 |
| 404 | 勋章 ID 不存在,或已被停用 |

---

### 5.3 创建勋章

```
POST /api/admin/badge
Content-Type: application/json
```

**请求体**:

```json
{
  "name": "新勋章名称",
  "thumbnail": "https://example.com/badge.png",
  "description": "可选描述,最多 200 字",
  "is_active": true
}
```

**字段约束**:

| 字段 | 必填 | 类型 | 约束 |
|---|:-:|---|---|
| name | ✅ | string | 1–40 字符,trim 后判空 |
| thumbnail | ✅ | string | http/https URL |
| description | ❌ | string | ≤ 200 字符 |
| is_active | ❌ | boolean | 默认 `true` |

**响应**: `201 Created`,返回完整勋章对象（含系统分配的 `id`）。

**错误码**:

| 状态码 | 含义 |
|---|---|
| 400 | 字段缺失或格式不合法 |
| 409 | 名称已被其他启用勋章占用 |
| 500 | 数据库异常 |

---

### 5.4 更新勋章

```
PUT /api/admin/badge/{id}
Content-Type: application/json
```

**请求体**: 任意子集,支持局部更新。

```json
{
  "name": "修改后的名称",
  "thumbnail": "https://example.com/new.png",
  "description": "更新后的描述",
  "is_active": false
}
```

**注意**: `id` 字段不可修改,提交会被拒绝。

**响应**: `200 OK`,返回更新后的完整勋章对象。

**错误码**:

| 状态码 | 含义 |
|---|---|
| 400 | ID 非法 / 字段不合法 / 尝试修改 ID |
| 404 | 勋章 ID 不存在 |
| 409 | 新名称与其他启用勋章冲突 |
| 500 | 数据库异常 |

---

### 5.5 启用勋章

```
POST /api/admin/badge/{id}/activate
```

**请求体**: 无。

**响应**:

```json
{
  "ok": true,
  "data": { "id": 10021, "is_active": true }
}
```

**特性**: 幂等 — 已启用的勋章再次调用不会报错。

---

### 5.6 停用勋章

```
POST /api/admin/badge/{id}/deactivate
```

**请求体**: 无。

**响应**:

```json
{
  "ok": true,
  "data": { "id": 10021, "is_active": false }
}
```

**特性**: 幂等 — 已停用的勋章再次调用不会报错。

---

### 5.7 鉴权说明

所有上述 API 均要求 **管理员登录态**。未登录或登录态失效时,接口返回权限错误（HTTP 401/403 视部署环境而定）。

获取 `admin_token` 的方式:

```
POST /api/admin/login
Content-Type: application/json

{ "password": "<管理员密码>" }
```

成功响应中 `Set-Cookie` 会下发 `admin_token`,后续请求需在 Cookie 中携带。

### 正常情况

| 测试项 | 预期结果 |
|---|---|
| 创建勋章 | 列表中新增一行,ID 系统自动分配 |

## 8. 注意事项

- **缩略图字段为图片 URL**: 系统只存储和展示传入的 URL,不做图片上传、压缩或 CDN 缓存。如需更换图片,请将新图片上传至稳定的图床后,把对应 URL 填入缩略图字段。

- **勋章不提供删除功能**: Phase 2 设计上禁止硬删除。若需下架,请使用「停用」功能。已停用的勋章保留全部历史记录,包括已发放给用户的奖励数据。

- **停用后的勋章保留**: 已停用勋章仍出现在列表的「停用区」,可随时重新启用,ID 与名称保持不变。活动配置侧不应再引用已停用的勋章。

- **已发放奖励不受影响**: 停用勋章后,已经发放到用户账户的勋章记录保持有效,前端展示与用户已获得的奖励数据不会因为勋章停用而消失。

- **名称唯一性范围**: 仅启用状态下校验名称唯一。已停用勋章的名称可被新建勋章复用。

- **ID 不可修改**: 勋章 ID 由系统自动分配,创建后任何 API 与后台操作均不可修改。
