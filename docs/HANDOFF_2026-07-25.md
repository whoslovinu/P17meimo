## 改动清单

### 数据库
- **新增**：`supabase/migrations/15_webhook_audit_table.sql`
  - 1 表：12 列 + 7 索引 + 0 RLS policy
  - 列：`tx_id, action_type, user_id, raw_user_id, client_ip, duration_ms, http_status, success, result, error_code, error_message, raw_body, created_at`
  - 索引：`tx_id`, `user_id`, `raw_user_id`, `created_at`, `(user_id, created_at)`, `(success, created_at)` (partial)
  - **RLS 故意不启用**（生产 RDS 没有 `service_role` Supabase 角色；访问由 app 池控制）

### 代码
- **新增**：`lib/db/pg.ts → insertWebhookAudit(input)`
  - 接受 `WebhookAuditInput` 对象（含 `rawBody` 自动截断 8KB）
  - 失败 fire-and-forget（不影响 webhook 响应）
- **修改**：`lib/auditLog.ts → logWebhookEvent()`
  - 新增 6 个可选字段：`httpStatus`, `userId`, `rawUserId`, `rawBody`, `errorCode`
  - 调用 `insertWebhookAudit().catch(...)` 异步持久化
- **修改**：`app/api/webhook/user-action/route.ts`
  - **6 处** `logWebhookEvent` 调用全部加上 `httpStatus` + `errorCode`
  - 失败路径带 `rawBody`（签名/Schema 错误时存原文→可分析签名顺序）
  - 成功路径带 `userId` + `rawUserId`（解耦 canonical UUID vs 入参）

### 错误码（新增）
```
INVALID_HMAC        — 401, 签名错误
MALFORMED_JSON      — 400, JSON parse 失败
SCHEMA_FAIL         — 400, Zod 校验失败
BODY_READ_FAIL      — 400, 无法读取 body
ALIAS_TIMEOUT       — 500, alias 解析超时
DB_FAIL             — 500, DB 写入失败
result 列：success / duplicate / refund-blocked
```

## 排查示例（写给下次接手的人）

```sql
-- 1. 客户给了一个 tx_id，找完整链路
SELECT * FROM public.webhook_audit WHERE tx_id = 'TEST_AUDIT_xxx' ORDER BY id;

-- 2. 某用户最近 1 小时所有 webhook 事件
SELECT id, action_type, http_status, success, result, error_code, created_at
FROM public.webhook_audit
WHERE user_id = '2747b7c7-...'
  AND created_at > NOW() - INTERVAL '1 hour'
ORDER BY created_at DESC;

-- 3. 失败率告警（最近 5 分钟）
SELECT error_code, count(*) AS n
FROM public.webhook_audit
WHERE success = false
  AND created_at > NOW() - INTERVAL '5 minutes'
GROUP BY error_code ORDER BY n DESC;

-- 4. 主站发什么 raw_user_id 进来最多
SELECT raw_user_id, count(*) AS n
FROM public.webhook_audit
WHERE created_at > NOW() - INTERVAL '1 day'
GROUP BY raw_user_id ORDER BY n DESC LIMIT 20;
```
