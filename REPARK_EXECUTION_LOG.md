### Cascade Architecture (Multi-Page 2048?2048 Atlas Support)

The spine-pixi-v8 loaders work as a three-stage cascade:

1. **`Spine.from()`** accepts asset aliases ? triggers the skeleton loader
2. **Skeleton loader** reads the `.json` ? extracts the referenced `.atlas` URL
3. **Atlas loader** parses the `.atlas` text file ? extracts every `page` filename (e.g. `boss.png`, `boss2.png`) ? PixiJS Assets loads each PNG from the same directory as the `.atlas`

Key insight: as long as all `.png` pages are co-located with the `.atlas` file, **no manual texture pre-registration is needed**. PixiJS v8's Asset resolver handles path resolution automatically.

Expected asset layout:
```
/public/spine/boss/assets/
  boss.json      ? skeleton data
  boss.atlas     ? texture atlas (references pages)
  boss.png       ? page 1 (? 2048?2048)
  boss2.png      ? page 2 (? 2048?2048) ? if needed
```

### WebGL Memory Optimizations

- **`resolution: window.devicePixelRatio || 1`** ? sets the framebuffer scale factor without inflating texture upload sizes. Textures remain at their native texel resolution (? 2048?2048 per page) while the canvas renders crisply on Retina/HiDPI displays.
- **`autoDensity: true`** ? synchronises the CSS canvas size with the device pixel ratio so the renderer never upscales texture data beyond what the GPU can handle.
- **`SpinePipe` renderer** ? spine-pixi-v8 installs a dedicated `SpinePipe` render target that batches all slot draw calls into a single WebGL/WebGPU draw call, reducing state changes and VRAM pressure.

## 2026-04-21 (Session 5) ? Dynamic Canvas Append: WebGL Context Isolation

**Trigger:** Commander confirmed the telemetry showed `1. Application init starting...` fired **twice**. Diagnosis: React Strict Mode was mounting two parallel `initSpine` runs, both binding to the same `<canvas ref={canvasRef}>` element. When Mount A's cleanup destroyed the shared canvas's WebGL context, Mount B was left trying to render to a dead canvas ? resulting in `Cannot read properties of null (reading 'split')` at `logPrettyShaderError`.

### Root Cause Analysis

The previous fix (elastic lock reset) prevents the second Strict Mode mount from *starting* a second init ? but the telemetry proves both mounts were entering init. This means `isInitializingRef.current` was `false` for both. The only explanation: Strict Mode was firing two effects before either cleanup ran (the standard double-invocation). With the shared `<canvas>`, whichever mount's cleanup ran first killed the other's WebGL context, and the survivor was a zombie.

### Fix: Dynamic Canvas Append (No Shared Canvas)

Instead of sharing one `<canvas>` element between mounts, PixiJS v8 now creates its own canvas per mount, and the component appends it to a `<div>` container dynamically. Each mount has a fully isolated WebGL context on its own canvas. When any mount's cleanup fires, `app.destroy()` tears down only that mount's canvas ? no other mount's canvas is affected.

  Client: 5s AbortController timeout → revert button to "Claimable"
  Server: Redis lock released in finally{} block
  Inventory: Only incremented after 200 OK received
```

Webhook checks recharge_processed BEFORE applying:
  IF recharge_processed == TRUE → return 200 (ack) but skip decrement
  This prevents refund events from rolling back consumed recharge credits.
```

```
Midnight UTC+8 = 16:00 UTC (cron expression: '0 16 * * *')

Functions:
  clear_expired_items() — zeroes item_hand/phallus when activity.end_time passed

```

#### Task 3: Anti-Overlap / Concurrency Defense (SFX Track)

**Problem:** Auto-clickers or rapid Attack button mashing (10x/sec) can trigger 10 simultaneous instances of the same SFX, causing audio clipping and distortion.

**Solution — Sliding Window Pool per URL:**

```
_sfxPool: Map<string, Howl[]>  // active instances keyed by URL
MAX_SFX_INSTANCES_PER_SOUND = 3  // hard cap per unique URL
```

**Concurrency Defense Algorithm (executed on every playSFX call):**

```
1. Get or create pool for URL
2. IF pool.length >= MAX_SFX_INSTANCES_PER_SOUND:
     oldest = pool.shift()   // FIFO eviction
     oldest.stop()            // kill oldest instance
3. Create new Howl, play(), push to pool
4. On `onend` callback: remove self from pool, clean up Map if empty
```

**Result:** Maximum 3 overlapping instances of the same SFX at any time. Different URLs are independent (e.g., attack_sound.mp3 and hit_effect.mp3 can each have 3 concurrent plays). Oldest instance is always evicted first — no clipping from rapid-fire triggers.

**Key insight:** Per-URL tracking (not global) ensures variety SFX (different sound types) remain uncapped, while repeated rapid-fire of the same sound is throttled.
